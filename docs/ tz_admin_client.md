# ТЗ: сайт разборов и админка (отдельный репозиторий)

Вторая из двух частей. Первая — `tz_research_content.md`, репозиторий бота, сдана
23.08.2026. Контентный слой сервера готов: проза, локали, структурированные
причины, привязка вердикта к срезу и расчёт свежести работают и покрыты тестами.

Один шаг — один вызов Codex. Шаги идут строго по порядку, каждый оставляет
репозиторий в компилирующемся состоянии.

**Общие правила для каждого вызова:**

- Перед изменением читать существующий код, типы и `contract/openapi.json`.
- Никаких обращений к API бота из браузера. Ни одного.
- Ключи только в серверных переменных окружения, без префикса `NEXT_PUBLIC_`.
- `null` ≠ `0`. Отсутствующее число печатается прочерком, а не нулём.
- Новых зависимостей не добавлять без явного обоснования в ответе.
- Стек фиксирован: Next 14.2.3 App Router, TypeScript, MUI, SCSS-модули, SWR.

---

## Граница продуктов

Проект бота отдаёт HTTP API и владеет данными. Этот проект к Postgres и Prisma
доступа не имеет и иметь не будет. Контракт берётся из `docs/openapi.json`
репозитория бота, типы генерируются здесь.

Из этого следует главное ограничение архитектуры: **браузер в API бота не ходит
вообще.** CORS там не настроен и настраиваться не будет — разрешённый источник в
CORS ничего не защищает, а браузерного потребителя у API нет. Значит любой
запрос к нему идёт из Route Handler, Server Action или серверного компонента,
которые подставляют `x-api-key`. SWR в браузере ходит только в собственные
`/api/**` этого проекта: тот же origin, CORS не нужен, ключ не покидает сервер.

Второе ограничение: **rate limit 60 запросов в минуту на адрес**, счётчик в
памяти инстанса бота. Запросы с админского ключа считаются отдельным ведром
(шаг E3 на стороне бота), поэтому всплеск на публичной части не выбивает
редактора посреди набора. Но лимит остаётся: форма, дёргающая пересчёт на каждое
нажатие клавиши, упрётся в него за полминуты работы.

## Ловушки контракта

Восемь. Каждая уже стоила отладки на стороне сервера, четыре последние — правок
в его коде. Клиент, написанный без них, будет тихо терять данные.

**1. `PUT` — полная замена, кроме паспорта протокола.** У методики, снимка,
вердикта и набора триггеров непереданное необязательное поле становится `null`:
на nullable-полях частичное слияние неотличимо от «стереть значение». Форма
обязана отправлять **все** поля сущности, даже те, которых не касалась.
Исключение одно — `PUT /api/v1/protocols/:slug`, он правит по одному полю
намеренно.

**2. Черновики требуют явного `includeDrafts=true`.** Наличие ключа выборку не
расширяет: серверные функции подставляют его в каждый запрос, и без флага
админка увидит ровно то же, что публика, — то есть не увидит ничего из того, что
редактирует.

**3. Неопубликованное отвечает `404`, а не `403`.** Существование черновика
наружу не подтверждается. В админке это значит: открывать черновик нужно ручкой
со флагом, а `404` на публичной ручке — нормальный ответ, а не сбой.

**4. Удаление протокола требует отдельного административного ключа.** Обычный
распознанный ключ получает `403`, неизвестный — `401`. Админский ключ живёт в
собственной переменной и используется ровно в одном Route Handler.

**5. Вердикт создаётся целиком одним запросом.** Причины и проза едут в теле
`POST` полем `content`. Публикация без него — `400`: опубликованный вердикт без
обоснования не должен существовать даже на миллисекунду, иначе публичная
страница успевает его отдать. Досылать причины и текст отдельными запросами
после создания **нельзя** — эта схема на сервере закрыта.

**6. Каждый `POST` вердикта создаёт НОВУЮ версию.** Сервер сам назначает `1.0`,
`1.1`, `1.2`. Два нажатия «Сохранить» в форме нового разбора дают два вердикта.
Форма обязана помнить: первое сохранение — `POST`, все последующие — `PUT` по
полученному номеру. Новая версия появляется только по явной кнопке.

**7. Порядок причин в одиночку не меняется.** Текст причины сопоставляется со
структурой **по позиции**. Перестановка `metricRef` при живых переводах молча
переадресовала бы готовую строку на другую метрику, поэтому `PUT .../reasons`
отвечает `400`, если у вердикта есть хотя бы один текст. Причины меняются только
вместе с текстами — через общее сохранение формы (`PUT` вердикта с `content`).

**8. Последний перевод опубликованного вердикта не удаляется.** `400`. Снять его
можно, только вернув вердикт в черновик. Кнопка «Удалить перевод» обязана быть
неактивна в этом состоянии, а не узнавать об отказе из тоста.

Плюс два наследственных факта, не ловушки, но знать надо:

- В теле `POST` и `PUT` вердикта остаётся **обязательное легаси-поле `reasons`**
  (свободный JSON, помечен `deprecated`). Настоящие причины — в
  `content.reasons`. Форма шлёт `reasons: {}` и не показывает это поле человеку.
- `excludedAddresses` методики — массив строк, не объект. В контракте починено,
  генератор типов отдаст `string[]`.

## Решения, принятые до шагов

**Контракт лежит в репозитории копией и сверяется скриптом.**
`contract/openapi.json` коммитится, `pnpm contract:pull` тянет свежую спеку с
задеплоенного `/api/v1/docs-json`, `pnpm contract:check` красит CI при
расхождении с закоммиченной. Ходить в спеку по сети на сборке нельзя:
недоступный API превратил бы деплой сайта в лотерею, а молча устаревшая копия —
это ровно тот класс дефекта, ради которого гейт и пишется.

**Типы генерируются, а не пишутся руками.** `openapi-typescript` из
`contract/openapi.json` в `src/contract/api.d.ts`, файл коммитится и правится
только генератором. Ручная копия типов разойдётся с сервером на первой же правке
контракта, и обе стороны будут «правы».

**Граница MUI и SCSS.** MUI — компоненты и тема: таблицы, формы, диалоги, поля
ввода. `styles.module.scss` — лейаут, сетки, типографика публичных страниц. `sx`
не используется нигде, кроме отступов. Два способа стилизации в одном компоненте
расходятся за эпик, поэтому граница проходит по компоненту, а не по строке.

**Плейсхолдеры подставляет сайт, а список полей отдаёт сервер.** Сервер
проверил, что каждый `{{snapshot.fdvRevenue}}` ссылается на существующее поле, и
на этом его работа кончилась: подстановка и формат числа — представление, им в
API делать нечего. Но перечень допустимых полей сайт **не выдумывает** — он
берётся из `GET /api/v1/metric-fields` (шаг E2 на стороне бота). Зашитая копия
списка разошлась бы с сервером на первом же новом поле, и редактор вставлял бы
из подсказки то, что сервер отвергает.

**Вход в админку — пароль в middleware.** Один редактор, httpOnly-кука, никакого
OAuth-провайдера. Появится второй редактор — заводится таблица пользователей на
стороне бота, не здесь.

**Автоперевода в этой версии нет.** Провайдер не выбран и ключа нет. Вкладка EN
работает как обычная форма ввода с ручной галочкой «машинный перевод». Кнопка
«Перевести» и Route Handler `/api/admin/translate` — отдельный шаг, когда
появится ключ. Схема данных к этому готова, дорабатывать её не придётся.

**Экрана триггеров в этой версии нет.** Модель, ручки и публичная выдача на
сервере работают, интерфейс отложен. Следствие для D7: блок триггеров
скрывается целиком, когда список пуст, — пустая рамка на витрине хуже её
отсутствия.

## D1. Каркас

**Цель.** Пустой, но запускающийся проект с зафиксированным стеком.

**Сделать.**

Next 14.2.3, App Router (`src/app/**`). Структура:

```
src/app/[locale]/(public)/...     публичные страницы
src/app/admin/...                 админка, вне [locale] — интерфейс только на русском
src/app/api/...                   Route Handlers
src/contract/                     сгенерированные типы и серверный клиент
src/components/                   MUI-компоненты
src/lib/                          чистые функции: формат чисел, плейсхолдеры, свежесть
```

Админка вне сегмента локали намеренно: переводится контент, а не интерфейс
редактора; двуязычная админка удвоила бы работу без единого читателя.

MUI: тема в `src/theme.ts`, обязательный `AppRouterCacheProvider` в корневом
лейауте — без него первый рендер приезжает нестилизованным и моргает.
`next/font` вместо ссылок на Google Fonts.

Переписать hygen-шаблоны `create:component` и `create:page` под App Router:
`page.tsx` + `styles.module.scss` + при необходимости `layout.tsx`. Старые
шаблоны генерируют структуру Pages Router и после этого шага врут.

`husky` + `lint-staged`: `eslint --fix` и `tsc --noEmit` на коммите. В
`package.json` заменить `test` на честную цель — текущая версия делает
`git add .` и не проверяет ничего, что можно назвать тестом.

`contentful` из зависимостей удалить: проза едет через API бота, второго
хранилища в этой схеме нет.

**Приёмка.** `pnpm build` проходит. `pnpm lint` и `tsc --noEmit` зелёные. Пустая
страница отдаётся со стилями MUI без моргания.

## D2. Контракт и серверный клиент

**Цель.** Типизированный доступ к API бота из серверного кода.

**Сделать.**

`contract/openapi.json` — копия спеки. Скрипты: `contract:pull` (забрать с
`RESEARCH_API_BASE_URL/api/v1/docs-json`), `contract:check` (сравнить с
закоммиченной, отличие — ненулевой код возврата). `contract:check` в CI и в
`lint-staged`.

`openapi-typescript` → `src/contract/api.d.ts`. Единственная новая зависимость
шага, обосновать в ответе.

`src/contract/client.ts` — серверный клиент, помеченный `import "server-only"`.
Импорт из клиентского компонента обязан ломать сборку, а не утекать ключ в
бандл. Требования:

- `x-api-key` из `RESEARCH_API_KEY`; админский ключ отдельной функцией и
  отдельной переменной;
- timeout 10 секунд на запрос, один retry только на сетевую ошибку и `5xx`;
  `4xx` не повторяется никогда — повтор `409` создаст второй конфликт вместо
  первого, а повтор `POST` вердикта создаст лишнюю версию;
- ошибки нормализуются в типизированный результат, а не бросаются: `400`, `401`,
  `403`, `404`, `409`, `429` — разные исходы, и UI обязан их различать. `429`
  говорит «превышен лимит, подождите», а не «ошибка сервера»;
- тело ошибки сервера (`message` из Nest) доносится до UI как есть. Валидация
  вердикта отвечает осмысленным текстом — «нельзя опубликовать без трёх причин»,
  — и заменять его на «ошибка сохранения» значит выбрасывать единственную
  подсказку редактору.

**Приёмка.** `contract:check` зелёный сразу после `contract:pull` и красный
после ручной правки `contract/openapi.json`. Попытка импортировать `client.ts` в
компоненте с `"use client"` ломает сборку. Ни одно поле в `api.d.ts` не имеет
типа `Record<string, never>`.

## D3. Доступ и Route Handlers

**Цель.** Ключ на сервере, админка за паролем.

**Сделать.**

`middleware.ts`: всё под `/admin` и `/api/admin` требует httpOnly-куку с
подписанным значением. Страница `/admin/login`, пароль из `ADMIN_PASSWORD`,
сравнение с выравниванием длины по времени. Кука `httpOnly`, `sameSite: lax`,
`secure` в проде.

Route Handlers `/api/admin/**` — тонкая прослойка: проверить куку, вызвать
клиент из D2, вернуть результат. Никакой бизнес-логики: она на сервере бота, и
вторая копия разойдётся с первой.

Пробрасывать `429` наружу как есть, не превращая в `500`. Клиент должен уметь
подождать, а не решить, что API сломан.

**Приёмка.** Без куки `/admin` редиректит на логин, `/api/admin/*` отвечает
`401`. Ключ не встречается в бандле: `grep` по `.next/static` пуст.

## D4. Админка: протоколы и методика

**Цель.** Завести протокол и описать, как считались числа.

**Сделать.**

Список протоколов — `?includeDrafts=true`, MUI `DataGrid`, колонки: `slug`,
название, сектор, публикация, дата последнего снимка. Черновики визуально
отделены: редактор обязан видеть, что публика этой строки не видит.

Форма паспорта: `slug` (только при создании — он естественный ключ и меняет
адрес страницы), название, тикер, сектор, сети, контракты, `defillamaSlug`,
`coingeckoId`, переключатель публикации. `PUT` здесь **частичный**: отправлять
только изменённое.

Форма методики: все поля `ResearchMethodology`. `PUT` — **полная замена**: форма
отправляет все поля, включая нетронутые. Незаполненное необязательное поле
уезжает как `null` осознанно, и это должно быть видно в интерфейсе.
`excludedAddresses` — редактор списка строк, не текстовое поле с JSON.

Версии методики: `POST` создаёт следующую, `PUT /methodology/:version` заменяет
существующую. В интерфейсе это две разные кнопки с разными подписями, а не одна
«Сохранить»: тихо создать вторую версию методики так же легко, как второй
вердикт.

Удаление протокола — диалог с подтверждением по вводу `slug`, отдельный Route
Handler с админским ключом. В диалоге прямо сказано, что каскадом уходит вся
история и что оценки соседей по сектору будут пересчитаны.

`409` на повторном `slug` — понятное сообщение у поля, не общий тост.

**Приёмка.** Создать черновик, увидеть его в списке, не увидеть на публичной
части. Записать методику, перечитать, убедиться в совпадении всех полей.
Двойное нажатие «Сохранить» не создаёт вторую версию методики.

## D5. Админка: снимок с живым пересчётом

**Цель.** Ввести шестнадцать чисел и видеть производные до сохранения.

**Сделать.**

Форма снимка вызывает `POST /api/v1/preview/metrics` и показывает шесть метрик и
три уровня оценки рядом с полями ввода. Ничего не записывается.

Обязательно:

- debounce 500 мс и отмена предыдущего запроса через `AbortController`. Без
  этого форма упрётся в лимит за полминуты набора даже со своим ведром;
- пустое поле уходит как `null`, а не `0`. Ноль — измеренное значение, пустота —
  его отсутствие, и подстановка нуля здесь испортит все производные;
- `null` в результате печатается прочерком с подписью, почему расчёт невозможен:
  `flowNeutralPrice: null` при `sprPct = 0` — это «не существует», а не «ошибка»;
- `sectorMedianFdvRevenue: null` сопровождается пояснением про недобор выборки
  сектора, иначе пустая клетка выглядит поломкой.

Список снимков протокола с редактированием и удалением. `PUT` — полная замена,
`takenAt` можно сменить, занятое значение даёт `409`.

**Диалог удаления снимка обязан предупредить о двух последствиях:** если на этот
снимок опирается вердикт, разбор потеряет опору и страница уйдёт в «данные не
подтверждены»; и медиана сектора пересчитается, то есть изменятся оценки у
соседних протоколов. Оба факта видны только после удаления, если о них не
сказать заранее.

**Приёмка.** Ввод чисел показывает те же значения, что вернутся после
сохранения. Быстрый набор в поле не даёт `429`. Сохранённый снимок совпадает с
предпросмотром до последнего знака. Удаление опорного снимка показывает
предупреждение и после подтверждения переводит страницу в «не подтверждено».

## D6. Админка: вердикт — суждение, причины, проза, локали

**Цель.** Самый нагруженный экран. Здесь же живёт вся механика из ловушек 5–8,
и написанный мимо неё экран будет отвечать `400` на каждое второе действие.

**Сделать.**

### Одна форма, одно сохранение

Экран собирает вердикт целиком: суждение, три причины, русский текст. Отдельных
кнопок «сохранить причины» и «сохранить текст» **нет** — сервер такую последова-
тельность не примет.

Первое сохранение:

```
POST /api/v1/protocols/:slug/verdicts
{
  snapshotTakenAt, isPublished, riskLabel, killersFired,
  reasons: {},                       // легаси, человеку не показывается
  changeReason, publishedAt,
  content: {
    reasons: [ { position: 1..3, metricRef } × 3 ],
    texts:   [ { locale, body, counterarguments, reasonTexts[3],
                 changeSummary, isMachineTranslated } ]
  }
}
```

Ответ несёт назначенную сервером `version`. Форма её запоминает, и все
последующие сохранения идут `PUT .../verdicts/:version` с тем же телом. Кнопка
«Новая версия разбора» — единственное место, откуда снова уходит `POST`.

Пока `POST` в полёте, кнопка сохранения заблокирована: повторное нажатие создаст
вторую версию, и откатить это можно только удалением.

### Блок суждения

`riskLabel`, `killersFired`, **опорный снимок** (`snapshotTakenAt`, выпадающий
список снимков протокола), `publishedAt`, переключатель публикации.

Опорный снимок — **обязательное поле**, по умолчанию последний. Сервер примет и
пустое значение, но такая страница навсегда покажет «данные не подтверждены»
независимо от качества данных. Это единственное поле, где интерфейс строже
сервера, и так и задумано.

Правило «непустой список убийц ⇒ только `HIGH`» дублируется в UI как подсказка,
но **не** как единственная проверка: авторитет — сервер, и `400` от него обязан
отображаться. UI подсказывает раньше, сервер решает.

### Блок причин

Ровно три строки, у каждой выпадающий список `metricRef` и текст. Повтор
`metricRef` блокируется — три причины со ссылкой на одно поле это одна причина,
написанная трижды.

Порядок причин меняется перетаскиванием, но сохраняется **только** общей кнопкой
формы. Отдельный запрос на причины сервер отвергнет, как только появится хоть
один перевод (ловушка 7).

### Редактор прозы

`body` и `counterarguments`, Markdown в `<textarea>`, превью справа с
подставленными числами из опорного снимка.

Список допустимых плейсхолдеров тянется из `GET /api/v1/metric-fields`
(кэшируется на сервере сайта, ходить за ним на каждое нажатие не нужно). Из него
строится:

- панель вставки полей — кнопкой, а не набором руками;
- подсветка неизвестного плейсхолдера **до отправки**. Опечатка обязана
  подсвечиваться в редакторе, а не приезжать `400` после нажатия «Сохранить»;
- подстановка значений в превью: `null` печатается прочерком, ноль — нулём.
  Здесь это особенно важно: «Net Token Flow 0%» и «нет данных» — прямо
  противоположные утверждения.

Подписи метрик на двух языках лежат в `src/lib/metric-labels.ts` и покрыты
гейтом из D10: новое поле на сервере без подписи здесь красит сборку, а не
печатает сырой ключ.

### Локали

Вкладки RU и EN. У каждой собственный статус: «нет перевода», «переведено
машиной», «выверено».

- RU пишется в общей форме вместе со всем остальным.
- EN сохраняется отдельно: `PUT .../verdicts/:version/texts/en`. Это единственный
  путь для перевода — он не трогает ни структуру причин, ни само суждение.
- Галочка `isMachineTranslated` ставится вручную; любая правка полей EN её
  снимает.
- Кнопка «Удалить перевод» неактивна, если это последний текст опубликованного
  вердикта (ловушка 8). Подсказка объясняет: сначала верните вердикт в черновик.

Переводятся `body`, `counterarguments`, тексты причин и `changeSummary`. Числа,
`metricRef` и номер версии — общие, в перевод не попадают.

Автоперевода в этой версии нет — см. «Решения, принятые до шагов».

### Описание изменений

`changeSummary` — **обязательное поле при создании новой версии**, начиная со
второй. Из него собирается история, и пустое значение делает её бесполезной.

Правка существующей версии (`PUT`) его не требует: исправление опечатки — не
пересмотр разбора, и заставлять писать объяснение на каждую запятую значит
получить объяснения вида «правки».

### Публикация

Черновик публикуется переключателем — это `PUT` с `isPublished: true`. Сервер
проверит, что у вердикта есть три причины и хотя бы одна локаль, и ответит `400`
с текстом, если нет. Английский для публикации **не требуется**.

**Приёмка.** Опубликовать вердикт с тремя причинами и русским текстом одним
сохранением. Двойное нажатие «Сохранить» не создаёт версию 1.1. Опечатка в
плейсхолдере подсвечена до отправки. Добавить EN, поправить руками, убедиться,
что флаг машинного перевода снят. Попытка удалить единственный перевод
опубликованного вердикта не даёт нажать кнопку. Попытка опубликовать черновик без
причин показывает сообщение сервера, а не «ошибка сохранения».

## D7. Публичная страница разбора

**Цель.** То, ради чего всё остальное.

**Сделать.**

`/[locale]/protocols/[slug]` — серверный компонент,
`GET /api/v1/protocols/:slug?locale=`. ISR с ревалидацией; после сохранения в
админке — `revalidatePath` на обе локали.

Блоки: паспорт, ключевые метрики, три уровня оценки, вердикт с меткой риска,
причины со ссылками на соответствующие числа, проза, контраргумент, триггеры,
дата среза.

Обязательно:

- **дата среза видна всегда.** Разбор без метки времени — это утверждение без
  срока годности;
- `riskLabel = HIGH` → блок уровней оценки не показывается вовсе. Сервер их и не
  пришлёт;
- `null` печатается прочерком с пояснением, никогда нулём и никогда пропуском
  строки;
- числа форматируются через `Intl.NumberFormat` по локали, названия метрик
  остаются английскими в обеих версиях — они не переводятся;
- перевода нет (`text: null`, локаль отсутствует в `availableLocales`) → плашка
  «доступно на русском» и ссылка. Ни пустой страницы, ни молчаливой подмены
  языка;
- блок триггеров **скрывается целиком**, если список пуст. Экрана управления
  ими в этой версии нет, и пустая рамка будет у большинства протоколов.

### Плашка свежести

Берётся из `freshness.status` в ответе. Пороги здесь не пересчитываются — сервер
уже посчитал и прислал в `deviations` метрику, старое и новое значение и порог.

| Статус | Заголовок | Что говорит читателю |
|---|---|---|
| `CURRENT` | Актуально | вердикт вынесен по свежим данным, расхождений нет |
| `DATA_CHANGED` | Данные обновились | пришёл новый срез, и метрика ушла за порог; называется какая, было/стало и дата |
| `VERDICT_REVISED` | Вердикт пересмотрен | данные новее опоры разбора, автор вердикт правил, но на новый срез его не переносил |
| `DATA_UNVERIFIED` | Данные не подтверждены | разбор не привязан к актуальному срезу |

Текст `DATA_UNVERIFIED` — **один нейтральный на все случаи**. Сервер даёт этот
статус в трёх разных ситуациях (сбой источника, отсутствие опоры, отсутствие
вердикта), и различать их в этой версии сознательно не будем: формулировка не
должна утверждать причину, которой может не быть.

**Приёмка.** Разбор открывается на обеих локалях. Протокол высокого риска — без
уровней. Отсутствующая выручка — прочерк, не ноль. Свежеопубликованный разбор
показывает «Актуально», а не «Вердикт пересмотрен». Изменение снимка на 25%
поднимает плашку «Данные обновились» после ревалидации.

## D8. Секторная таблица

**Цель.** Самый репостируемый формат и предфильтр для новых разборов.

**Сделать.**

`/[locale]/sectors/[sector]` из `GET /api/v1/sectors/:sector/table`. Колонки:
Revenue, Net Revenue, FDV/Revenue, VAR, SPR, Net Token Flow, метка риска, ссылка
на разбор. Сортировка по любому столбцу — на клиенте, данных десятки строк.

Протокол без вердикта показывается со всеми числами и пустой меткой риска:
таблица — предфильтр, и скрывать из неё неразобранное значит лишить её смысла.

**Приёмка.** Сортировка по каждой колонке, `null` внизу при любом направлении —
отсутствие данных не должно выглядеть как лучший или худший результат.

## D9. Локали, SEO, деплой

**Цель.** Две версии, индексируемые и не выдающие себя друг за друга.

**Сделать.**

`/[locale]` со значениями `ru` и `en`, редирект с корня по `Accept-Language`,
`hreflang` на обе версии, canonical на собственную. Страница без перевода
`hreflang` на несуществующую версию не ставит — а такие страницы будут штатно,
раз английский для публикации не обязателен.

`sitemap.ts` и `robots.ts` из списка опубликованных протоколов; в английский
sitemap попадают только те, у кого EN действительно есть. Open Graph с меткой
риска и датой среза.

Vercel: переменные `RESEARCH_API_BASE_URL`, `RESEARCH_API_KEY`,
`RESEARCH_API_ADMIN_KEY`, `ADMIN_PASSWORD`. Все — серверные, ни одной с
`NEXT_PUBLIC_`. Переменной провайдера перевода в этой версии нет.

Ротация ключей: сначала новое значение в Production-переменной Vercel, затем то
же значение в env бота, затем перезапуск бота. Обратный порядок создаёт окно, в
котором сайт шлёт уже недействительный ключ.

**Приёмка.** Обе локали в sitemap, непереведённые страницы — только в русском.
`grep` по бандлу не находит ни одного ключа. Прод отвечает, админка за паролем.

## D10. Проверки

**Цель.** Отличить «собирается» от «работает».

**Сделать.**

- `contract:check` в CI — гейт от расхождения со спекой.
- Юниты на чистые функции: подстановка плейсхолдеров, формат чисел по локали,
  `null` → прочерк, выбор текста плашки свежести по всем четырём статусам.
- Юнит: каждое поле из `GET /api/v1/metric-fields` (зафиксированный ответ в
  фикстуре) имеет подпись в обеих локалях. Новое поле на сервере без подписи
  здесь красит сборку, а не печатает сырой ключ.
- Юнит на состояние формы вердикта: после успешного `POST` следующее сохранение
  обязано уйти `PUT`. Это единственная защита от размножения версий, и проверять
  её руками бессмысленно — дефект виден только на второй раз.
- Смоук по живому деплою: главная, разбор, секторная таблица и `/admin/login`
  отвечают `200`; `/admin` без куки редиректит. Отдельная цель, запускается
  против URL.

Каждый гейт проверить на красноту: временно сломать источник и убедиться, что
упал именно он. Гейт, зелёный до и после правки, ничего не сторожит.

**Приёмка.** Все проверки зелёные. Каждая показана красной хотя бы раз.

## Зависимости от репозитория бота

Два шага на стороне API делаются параллельно D1–D5 и обязаны быть готовы к
началу D6:

**E2. `GET /api/v1/metric-fields`** — список допустимых полей для плейсхолдеров:
`metricRef`, путь (`snapshot.fdvRevenue`), источник (`snapshot` / `valuation`).
Источник данных — существующая карта `METRIC_REFS` в `verdict.logic.ts`, новых
констант не появляется.

**E3. Отдельное ведро rate limit под админский ключ** — чтобы всплеск на
публичной части не выбивал редактора.

До их появления D1–D5 выполняются полностью: ни список полей, ни лимит там не
нужны.

## Чего в этом ТЗ нет намеренно

WYSIWYG-редактора, загрузки изображений, комментариев, подписки, экспорта
таблицы картинкой, аналитики, нескольких редакторов, автоматического сбора чисел
из внешних источников.

Отложено явно, с готовой серверной частью:

- **экран триггеров** — модель и ручки работают, интерфейса нет; до него блок на
  публичной странице скрыт;
- **кнопка автоперевода** — схема хранения готова, нет провайдера и ключа;
- **разделение `DATA_UNVERIFIED` на три состояния** — сервер их различает
  внутри, наружу пока отдаёт одно.

Сначала должно работать то, ради чего сайт существует: разбор с числами, которые
можно обновить.
